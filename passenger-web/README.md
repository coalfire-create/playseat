# passenger-web

동승자 웹앱. **설치가 필요 없는 것이 핵심 전제**입니다.
차량 화면의 QR을 스캔하면 폰 브라우저에서 바로 열립니다.

빌드 과정이 없는 정적 파일이며 `hub-server` 가 서빙합니다.
`http://localhost:8080/?s=<sessionId>`

## 화면 구성

| 영역 | 내용 |
|---|---|
| 최초 진입 | 차 내부처럼 보이는 1열·2열 좌석 배치도에서 앉은 좌석을 선택. 착석이 감지된 좌석만 선택 가능 |
| 내 차례 | 점멸하는 표시와 함께 강조. 차례가 아니면 다음 차례 좌석을 안내 |
| 상태 띠 | 충전 라운지 / 도착 5분 전 / 주행 중 권한 이전 안내 |
| 지금 재생 | 앨범아트·진행 바·선곡 좌석·재생 위치, ♥·건너뛰기(투표 수 표시) |
| 곡 추가 | 검색 결과에 앨범아트. 차례가 아니면 추가 버튼이 비활성 |
| 대기 중인 곡 | 선곡 좌석 표시, 내 선곡은 강조. 큐 길이와 도착까지 남은 시간 비교 |
| 드라이브 앨범 | 주행이 끝나면 카드로 나타남 |

`deviceId` 는 `localStorage` 에 저장해 재접속 시 좌석에 자동 복귀합니다.
최초 1회만 좌석을 고르면 다음부터는 타기만 하면 연결됩니다.

### 앨범아트
`search.result` 의 `artworkUrl` 이 있으면 그 이미지를 쓰고, 없으면 곡명으로 결정되는
그라데이션 타일을 만듭니다. 큐레이션 목록의 곡은 커버 이미지가 없는데 빈 자리로 두면
이미지가 깨진 것처럼 보이기 때문입니다. 같은 곡은 항상 같은 색이 나와 목록에서
곡을 구분하는 데도 쓰입니다. 외부 이미지 로딩이 실패해도 조용히 타일로 바뀝니다.

### 의존성
없습니다. 단일 HTML 파일이며 외부 스크립트·폰트·CDN 을 쓰지 않습니다.
네트워크가 끊겨도 화면은 뜨고, 시연이 외부 서비스에 좌우되지 않습니다.

## 설계 원칙

- **스스로 판단하지 않습니다.** 화면은 차량이 보낸 `state.sync` 를 그대로 그립니다.
- **낙관적 업데이트 금지.** 차량이 요청을 거절할 수 있으므로, 보내고 나서 다음
  `state.sync` 를 기다립니다. 먼저 UI에 반영하면 되돌려야 합니다.
- 주행 중(`driveState === "DRIVING"`)에는 운전자 화면이 잠기고 조작 권한이 이 폰으로
  넘어옵니다. 이때 UI를 더 넓게 쓰는 것이 의도된 동작입니다.
