## 0. 병행 개발의 전제 — 계약을 먼저 고정한다

두 사람이 만드는 것은 **차량 앱**과 **동승자 웹(+서버)** 이고, 이 둘은 WebSocket 메시지로만
대화합니다. 그래서 **오늘 밤에 `contract_protocol.md`를 확정하고 양쪽이 서로를 목(mock)으로
대체**하면, 그 뒤로는 상대를 기다릴 일이 없습니다.

- 이정한은 `FakeVehicleSignalSource`로 좌석·도어·기어 신호를 가짜로 넣어 에뮬레이터 없이도 개발.
- 이용준은 `MockCarClient`로 차량 앱 흉내를 내서 차량 앱 없이도 웹앱 완성.
- **이용준이 가장 먼저 할 일은 에코 허브(WebSocket relay 최소 버전) 띄우기.** 이게 늦으면
  이정한이 붙을 데가 없어 전체가 막힙니다. 오늘 안에 끝내는 것을 1순위로.

### 세션의 주인은 차량 앱이다 (중요)
턴 순서·좌석 권한·스킵 집계 같은 **모든 판정은 차량 앱이 하고**, 서버는 중계와 곡 검색만
합니다. 서버가 세션을 들고 있으면 "차 없이도 되는 서비스 아니냐"는 심사 반박을 받습니다.
웹앱은 요청만 보내고, 화면은 차량이 보내 준 `state.sync`를 그대로 그립니다.

## 1. 저장소 구조와 작업 규칙

```
playseat/
├── car-app/         Android 차량 앱            ← 이정한 전담
├── hub-server/      Ktor WebSocket 허브        ← 이용준 전담
├── passenger-web/   동승자 웹앱                ← 이용준 전담
├── demo/            Virtual Console 자동화·녹화 ← 이용준 전담
├── contract/        protocol.md, schema.json   ← 공동 (변경은 양쪽 합의 필수)
├── apk/             제출용 release APK
└── docs/            README, SETUP
```

규칙
- `main` 보호. 직접 푸시 금지, PR로만 병합.
- 브랜치 이름: `feat/car-*`, `feat/hub-*`, `feat/web-*`, `feat/demo-*`
- **서로의 디렉터리 파일은 직접 수정하지 않는다.** 필요하면 이슈로 요청.
- `contract/`를 바꿀 때는 PR에 상대를 리뷰어로 지정하고 승인 후 병합. 계약이 조용히 바뀌면
  양쪽이 동시에 깨집니다.
- `local.properties`, API 키, 서명 키는 커밋 금지.

## 2. 파트 분담

### 이정한 — 차량 앱 (Android / Kotlin / Jetpack Compose / Pleos Connect SDK)

| 모듈 | 내용 |
|---|---|
| `VehicleSignalRepository` | Vehicle SDK로 좌석 착석(`CAR_SEATS`), 도어(`CAR_DOORS`), 기어·주행(`CAR_DRIVE`), 충전(`CAR_ENERGY`) 수신. `FakeVehicleSignalSource`로 교체 가능하게 인터페이스 분리 |
| `SessionEngine` | 좌석 슬롯 생성·회수, 턴 순서 계산, 좌석 프로필 권한 검증, 스킵 투표 집계. **단일 진실 공급원** |
| `DriveModeController` | 주행·정차 전환 → UI 권한 상태(`PARKED`/`DRIVING`) 결정, 주행 중 검색·스크롤·키보드 차단 |
| `VoiceController` | SpeechToText로 운전자 명령, TextToSpeech로 턴·다음 곡 안내 |
| `PlaybackGateway` | AAOS MediaSession/MediaController 위임 + 오디오 포커스. 1단계는 차량 기본 음악 앱 위임 |
| `NaviRepository` | NaviHelper로 목적지·잔여 ETA → 큐 목표 길이, 랜딩 트랙 시점 |
| `HubClient` | WebSocket 클라이언트, `state.sync` 송신 / 요청 수신 |
| Car UI | 좌석 배치도, now playing, QR 표시, 정차 시 전체 큐 |

### 이용준 — 허브 서버 + 동승자 웹 + 시연 산출물

| 모듈 | 내용 |
|---|---|
| `hub-server` | Ktor WebSocket 허브. 세션방 관리, 차량↔폰 메시지 중계, 디바이스 재접속 처리 |
| 곡 검색 | 곡명·아티스트 메타데이터 검색 API (서버가 처리, 차량 앱 경유 안 함) |
| `passenger-web` 진입 | QR 스캔 → 좌석 자동 배정 → 닉네임. **설치 없는 웹앱**이 핵심 전제 |
| `passenger-web` 메인 | 내 차례 표시, 곡 검색·추가, 큐 보기, ♥·스킵 투표, 좌석 프로필(아동 제한) 화면 |
| `MockCarClient` | 차량 앱 역할을 흉내 내는 스크립트. 웹앱 단독 개발·테스트용 |
| `demo/` | Pleos Emulator Virtual Console 자동 조작 스크립트 (도어·착석·기어·속도·충전 주입) |
| 제출물 | 시연 영상 녹화·편집·자막, 화면 시안(Figma), 숏폼 |

### 공동
계약 확정, 사용 시나리오 설계, 통합 체크포인트 점검, 기획서 보완.
README는 이정한, 시연 영상·시안은 이용준이 최종 책임.
