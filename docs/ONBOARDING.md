# 시작하기 (제출물 담당)

클론하고 30분 안에 전체 루프를 눈으로 보고, 바로 자기 작업에 들어가는 것이 목표입니다.

## 1. 클론과 git 설정

```bash
git clone https://github.com/coalfire-create/playseat.git
cd playseat
```

**커밋 작성자 설정을 먼저 하세요.** 공모전 안내에 "공유 링크와 첨부자료에 개발자 실명이
노출되지 않도록" 이라는 조항이 있습니다. 본명이나 학교 이메일이 커밋에 박히면 저장소를
심사용 계정에 공유할 때 그대로 노출됩니다.

```bash
git config user.name "YJ-cell973"
git config user.email "YJ-cell973@users.noreply.github.com"
```

필요한 것: JDK 17, Node 22 이상. (Android SDK는 차량 앱 담당만 필요합니다)

## 2. 전체 루프 돌려 보기

터미널 2개.

```bash
# 터미널 1 — 허브 서버. 동승자 웹앱도 같이 서빙합니다
cd hub-server && ./gradlew run

# 터미널 2 — 차량 앱 목(mock). 차량 앱 없이 개발하기 위한 장치입니다
node demo/mock-car.mjs
```

브라우저에서 `http://localhost:8080` 을 엽니다.

1. 좌석 칸을 눌러 참여합니다 (이름 입력)
2. 곡을 검색해 추가합니다 — 차례가 없으므로 언제든, 몇 곡이든 됩니다
3. 터미널 2에서 `d` 를 누르면 주행 상태로 바뀝니다. 폰이 조작 권한을 받는 구간입니다
4. `1`~`5` 로 좌석 착석을 토글합니다. 하차시키면 그 좌석의 미재생 곡이 큐에서 사라집니다

이게 CP1·CP2가 요구하는 동작입니다. 이미 돌아갑니다.

## 3. 이미 만들어져 있는 것

분담안의 "에코 허브 먼저 띄우기"는 **끝났습니다.** 그뿐 아니라 세션방 관리, 곡 검색 스텁,
동승자 웹 기본형, 차량 앱 목까지 먼저 작성되어 있습니다.

| 것 | 상태 |
|---|---|
| `hub-server` WebSocket 중계 | 동작. 통합·단위 테스트 |
| `demo/mock-car.mjs` | 동작. 좌석 권한·스킵 과반 판정까지 (선곡 차례는 v0.6 에서 없어졌습니다) |
| `passenger-web` | 동작. 차량 화면과 같은 디자인 언어(Pleos 팔레트·헤어라인·주야간) |
| `car-app` 세션 엔진·화면·Pleos SDK 연동 | 동작. 단위 테스트 |

테스트는 **133개 전부 통과**합니다 (차량 82 · 허브 51). `./gradlew test` 로 돌아갑니다.

**이 코드들은 설계 초안이고 소유권은 당신에게 있습니다.** 고치거나 다시 써도 됩니다.
`CONTRIBUTING.md` 의 "초기 구현에 대한 안내"를 보세요.

### PT 를 염두에 두세요
심사위원이 팀원 각자에게 질문하는 경우가 흔합니다. 코드를 직접 쓰지 않아도
구조는 설명할 수 있어야 합니다. 특히 다음 세 가지는 반드시 알고 가세요.

- **좌석 착석 신호로 세션이 자동 성립하는 구조** — 초대도 세션 개설도 없습니다.
  차가 누가 어디에 탔는지 알기 때문에 가능하고, 스마트폰 앱은 구조적으로 못 합니다.
- **주행 중 조작 권한이 동승자 폰으로 이전되는 이유** — 운전자는 조작 권한이 있지만
  주행 중엔 써서는 안 됩니다. 주의 분산 규제를 제약이 아니라 기능으로 바꾼 것입니다.
- **음원을 보유하지 않는 레이어 구조** — 지금은 실제로 소리가 납니다. 공개 API 의
  30초 미리듣기를 허브가 `GET /audio` 로 중계하고 차량이 오디오 포커스·MediaSession
  으로 재생합니다. 그래도 **전체 음원은 보유하지 않으며**, 화면에 "미리듣기 30초" 를
  그대로 적습니다. 큐레이션 74곡 중 미리듣기 음원이 붙는 것은 40곡이고, 나머지
  34곡은 소리 없이 큐만 흐릅니다 — 물으면 이 숫자를 그대로 답하세요. 정식 서비스에서는 `PlaybackGateway` 인터페이스 하나를 사업자 음원
  세션으로 교체합니다 — 세션 로직·차량 화면·폰은 재생 방식을 모릅니다. 저작권
  리스크가 구조적으로 없는 이유가 여기 있고, PT 에서 반드시 나오는 질문입니다.
  답할 거리는 [`BUSINESS.md`](BUSINESS.md) 에 정리해 두었습니다.

## 6. 계약서를 먼저 읽으세요

`contract/protocol.md` 가 차량 앱과 당신 코드의 **유일한 접점**입니다.
현재 **v0.7** 이며, 맨 앞의 **구현 상태표**를 반드시 보세요.

v0.2 의 `mode`·`landing`·`queueTotalMs`·`drive.album` 은 모두 구현됐습니다.
그 뒤로 바뀐 것 중 설명할 때 필요한 것만 적습니다.

- **v0.6 — 선곡 차례가 없어졌습니다.** `turnSeatId`·`turnDeadlineMs`·
  `turnRemainingMs`·`turn.pass`·`NOT_YOUR_TURN` 이 전부 사라졌습니다.
  앉아 있는 좌석은 누구나, 언제든, 몇 곡이든 넣습니다.
- **v0.7 — 네 가지가 들어왔습니다.** 실제 재생(`previewUrl`·`playableMs`),
  도착 맞춤 편성(`arrivalSlackMs`·`cutIndex`·`fitPlan`·`canFitArrival`·`queue.fit`),
  좌석 지분(`shares`·`shareNote`), 탑승 코드(`joinCode`).

`etaSeconds` 는 실차 내비에서 받는 부분만 미검증입니다(목·Fake 신호원에서는
실제로 흐릅니다). 목적지가 없으면 도착 맞춤 편성 관련 네 필드는 비어서 내려오므로,
폰은 그 필드가 `undefined` 인 상태를 정상으로 다뤄야 합니다.

계약을 바꿔야 하면 혼자 고치지 말고 알려 주세요. 조용히 바뀌면 양쪽이 동시에 깨집니다.
